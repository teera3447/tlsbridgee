# TLS Bridge

แอป Android (minSdk 14 = Android 4.0 ขึ้นไป) ที่รันเป็นบริการเบื้องหลังตั้งแต่เปิดเครื่อง
พก TLS สมัยใหม่ (Conscrypt/BoringSSL, TLS 1.3 + 1.2) มาในตัว และใช้สิทธิ์ root ช่วยยกระดับทราฟฟิกของแอปอื่น

> สถานะ: เขียนและตรวจไวยากรณ์แล้ว แต่ **ยังไม่เคยคอมไพล์หรือรันบนอุปกรณ์จริง**
> ทดสอบบน Android รุ่นเก่าและแก้ตามผลที่ได้ก่อนใช้งานจริง

## สร้างไฟล์ APK

1. เปิดโฟลเดอร์นี้ด้วย Android Studio (JDK 17 ขึ้นไป) แล้วรอ Gradle sync
   - ตัว build จะดาวน์โหลดรายชื่อ CA ของ Mozilla ไปไว้ที่ `app/src/main/assets/cacert.pem` อัตโนมัติ
     ถ้าออฟไลน์ ให้โหลด https://curl.se/ca/cacert.pem มาวางที่นั่นเอง
2. เมนู Build > Build Bundle(s) / APK(s) > Build APK(s)
   หรือบนเทอร์มินัล `./gradlew assembleDebug`
3. ได้ไฟล์ `app/build/outputs/apk/debug/app-debug.apk` ส่งเข้าเครื่องแล้วติดตั้ง (เปิด "แหล่งที่ไม่รู้จัก")

ถ้า Gradle ไม่ยอมรับ `minSdk 14` ให้แก้ `app/build.gradle` เป็น 16 หรือ 21 แล้วบอกผมเพื่อปรับต่อ

## ใช้งาน

1. เปิดแอปครั้งแรก 1 ครั้ง (Android จะส่งสัญญาณ BOOT_COMPLETED ให้แอปหลังเคยเปิดแล้วเท่านั้น)
2. กด "ตรวจสอบ root" แล้วอนุญาตในแอปจัดการ root
3. กด "ทดสอบ TLS (ตรงจากแอป)" ควรเห็น `tls_version=TLS 1.3`
4. กด "ทดสอบผ่านบริดจ์" ควรเห็น `TLS 1.3` เช่นกัน ทั้งที่ส่งคำขอเป็น http://
5. รีสตาร์ตเครื่อง บริการจะเริ่มเองและตั้งกฎ iptables ให้เอง (มีการลองซ้ำประมาณ 1 นาทีรอ su พร้อม)

## สิ่งที่ทำจริง

- บริดจ์ฟังที่ `127.0.0.1:8118` เท่านั้น (ไม่เปิดให้เครื่องอื่นในเครือข่าย)
- คำขอ `http://` จะถูกดึงผ่าน `https://` ด้วย TLS 1.3/1.2 แล้วส่งกลับให้แอปเก่าเป็น HTTP ธรรมดา
  - ตรวจใบรับรองและชื่อโฮสต์ทุกครั้ง ไม่มีการปิดการตรวจ ใช้รายชื่อ CA ของ Mozilla ที่แนบมา
    ร่วมกับ CA ของเครื่อง จึงแก้ปัญหา root CA หมดอายุบน Android 4.x ได้
  - Redirect แบบ `https://` จะถูกแปลงให้ไม่หลุดออกนอกบริดจ์ และตัด `Secure` ออกจากคุกกี้
    เพราะไคลเอนต์รับผ่าน http
  - ถ้าเว็บไม่รองรับ HTTPS จะจำไว้ 10 นาทีแล้วใช้ HTTP เดิม (ปิดได้ในหน้าจอ)
- ถ้าเปิดตัวเลือก root จะตั้ง `iptables -t nat` (chain `TLSBRIDGE`) ให้ทุกแอปที่ส่งพอร์ต 80
  ถูกเปลี่ยนเส้นทางมาที่บริดจ์ ยกเว้นตัวแอปนี้เองและปลายทาง loopback
- `CONNECT` (HTTPS ผ่าน proxy) ถูกส่งต่อแบบตรง ๆ ไม่ถอดรหัส

## ข้อจำกัดที่ต้องรู้

- **ทราฟฟิก HTTPS พอร์ต 443 ของแอปอื่นไม่ได้ถูกยกระดับ** แอปเก่ายังเจรจา TLS เองด้วยเวอร์ชันเดิม
  การทำให้ครอบคลุมต้อง MITM (ติดตั้ง CA ของเราในเครื่อง ถอดรหัสแล้วเข้ารหัสใหม่) ซึ่งยังไม่ได้ใส่ไว้
- เครื่อง CPU แบบ armeabi (ARMv5/v6) ไม่รองรับ Conscrypt ที่แนบมา (รองรับ armeabi-v7a, arm64-v8a, x86, x86_64)
- ไม่รองรับ request body แบบ chunked จากไคลเอนต์ (ตอบ 411) และจำกัดขนาด body 8 MB
- ไม่ใช้ HTTP/2 (OkHttp 3.12 บน Android ไม่ทำ ALPN ให้ Conscrypt ที่แนบมา) ใช้ HTTP/1.1 พร้อม connection pool
- ใช้ IPv4 เท่านั้นสำหรับกฎ iptables

## ความเสี่ยงและการกู้คืน

- กฎ iptables ชี้พอร์ต 80 ไปที่บริดจ์ ถ้าบริการตายแต่กฎยังอยู่ เว็บ HTTP จะเข้าไม่ได้
  บริการจะลบกฎให้เองเมื่อหยุดปกติ แต่ถ้าโปรเซสถูกฆ่า ให้รีสตาร์ตเครื่อง (กฎไม่ถาวร) หรือสั่ง
  `su -c "iptables -t nat -D OUTPUT -p tcp --dport 80 -j TLSBRIDGE; iptables -t nat -F TLSBRIDGE; iptables -t nat -X TLSBRIDGE"`
- ไม่มีการแก้ไข /system และไม่ remount อะไรเลย จึงไม่เสี่ยง brick เครื่อง
- เคอร์เนลบางรุ่นไม่มีโมดูล `owner` หรือ `REDIRECT` ถ้าเป็นเช่นนั้นบันทึกในแอปจะแจ้งข้อผิดพลาด
  และบริดจ์ยังใช้เป็น HTTP proxy แบบตั้งค่าเองได้ (127.0.0.1:8118)

## โครงสร้างโค้ด (`app/src/main/java/app/tlsbridge`)

| ไฟล์ | หน้าที่ |
|---|---|
| `TlsEngine` | ติดตั้ง Conscrypt, สร้าง trust manager (CA ที่แนบ + ระบบ), OkHttp client |
| `ProxyServer` | HTTP proxy บน loopback: อัปเกรด http→https, tunnel CONNECT |
| `BridgeService` | บริการ foreground (START_STICKY) เริ่ม proxy และตั้งกฎ root |
| `BootReceiver` | เริ่มบริการตอนบูต/อัปเดตแอป |
| `RootShell`, `Iptables` | เรียก `su` และจัดการ chain iptables |
| `MainActivity` | หน้าจอเปิด/ปิด สถานะ บันทึก และปุ่มทดสอบ |
